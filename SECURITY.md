# Security Policy

Liftr is infrastructure control-plane software. Please report suspected
security vulnerabilities privately so maintainers have an opportunity to
investigate and coordinate a fix before details become public.

## Supported Versions

Liftr is currently pre-1.0 and has not published a production-supported
release. Security fixes are made on the default branch. When versioned
releases begin, this section will identify the supported release lines.

## Reporting a Vulnerability

Use GitHub's private vulnerability reporting for this repository:

<https://github.com/sithea-nou/liftr/security/advisories/new>

Include, when possible:

- the affected component and revision;
- the impact and likely attack scenario;
- minimal reproduction steps or a proof of concept;
- any suggested mitigation; and
- whether you have disclosed the issue anywhere else.

Do not include credentials, tokens, customer data, cloud state, or other
sensitive material in the report. Redact logs and examples.

If private vulnerability reporting is unavailable, open a minimal public
issue asking the maintainer to establish private contact. Do not include
vulnerability details in that issue.

The maintainer aims to acknowledge a report within three business days. The
time needed to validate and fix an issue depends on its complexity. Please
allow reasonable time for remediation before public disclosure.

## Scope

Reports about Liftr source code and its published artifacts are in scope.
Vulnerabilities in third-party services, cloud providers, provisioners, or
operator-managed deployments should also be reported to the responsible
vendor or operator when appropriate.
